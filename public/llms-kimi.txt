## 1.3 Installing TypeScript Kimi Code CLI (`kimi` & `kimi web`)

Rewritten in TypeScript for fast startup and isolated subagent orchestration, **Kimi Code** runs in three modes—interactive terminal (`kimi`), local browser dashboard (`kimi web`), and editor protocol daemon (`kimi acp`):

```bash
# 1. Install TypeScript Kimi Code CLI (Node.js >= 20)
npm install -g @moonshot-ai/kimi-code

# 2. Export API key from your local secrets environment
export MOONSHOT_API_KEY="sk-your-moonshot-key"

# 3. Verify installation and launch in a repository root
kimi --version
cd /path/to/your-repo
kimi

# 4. Or launch the local visual session dashboard (loopback only)
kimi web --port 4310
```

## 2.1 `~/.kimi-code/config.toml` & Shared `AGENTS.md`

Kimi Code separates runtime behavior (`~/.kimi-code/config.toml`) from UI styling (`~/.kimi-code/tui.toml`) and reads root `AGENTS.md` natively—zero duplicate rule files alongside Codex or Antigravity:

```toml
default_model = "kimi-k3.1-pro"
approval_mode = "always_ask"

[providers.moonshot]
base_url = "https://api.moonshot.ai/v1"
api_key_env = "MOONSHOT_API_KEY"
prompt_caching = true

[swarm]
max_concurrency = 4
worktree_isolation = true

[subagents.explore]
model = "kimi-k3.1-pro"
read_only = true

[subagents.plan]
model = "kimi-k3.1-pro"
read_only = true

[subagents.coder]
model = "kimi-k3.1-pro"
max_retries_per_error = 3

[mcp.figma]
command = "npx"
args = ["-y", "figma-developer-mcp"]
env = ["FIGMA_API_KEY"]
```

Keep `approval_mode = "always_ask"` on local workspaces; pass `--auto` only inside isolated containers or disposable Git worktrees.

# Ch.03 Tiered Subagents (`explore / plan / coder`) & Parallel Multi-Agent Refactors

> **Engineering pain solved**: Refactoring 40 files in a single chat fills context with stale stack traces and breaks earlier edits—while uncapped parallel agents immediately trigger `429` rate limits.
>
> **What you ship**: A disciplined `explore → plan → coder` workflow, rate-controlled `/swarm` execution (`KIMI_CODE_AGENT_SWARM_MAX_CONCURRENCY`), and a three-strike loop breaker.
>
> **Bottom line**: Isolate noisy exploration from code editing, freeze shared types before fanning out, and let 90%-discounted prefix caching multiply swarm ROI.

---

## 3.1 Separating `explore`, `plan`, and `coder`

| Subagent | Permission Scope | Primary Deliverable | Why Context Isolation Matters |
| :--- | :--- | :--- | :--- |
| **`explore`** | Read-only | Symbol map, dependency graph, blast radius | Absorbs raw search noise; returns a concise 1-page map |
| **`plan`** | Zero writes | Phased rollout plan, disjoint directory slices, test commands | Surfaces architectural conflicts before touching source files |
| **`coder`** | Scoped writes + shell tests | Atomic diff + passing test output | Executes cleanly against frozen specs without stale chatter | ```mermaid
flowchart LR
    Req["Large Refactor Goal"] --> Exp["explore (Read-only repo scan)"]
    Exp -->|"Compact dependency map"| Plan["plan (Disjoint slices + assertions)"]
    Plan -->|"Human sign-off"| Swarm["/swarm (MAX_CONCURRENCY=4)"]
    Swarm --> C1["coder-1: Module A"]
    Swarm --> C2["coder-2: Module B"]
    Swarm --> C3["coder-3: Tests & Types"]
    C1 --> Merge["Full Build & Regression Gate"]
    C2 --> Merge
    C3 --> Merge
```

---

## 3.2 Throttled `/swarm` Execution & Cached-Prefix Economics

Cap parallel workers explicitly to avoid `429` storms while keeping all workers hitting the same **\$0.20/1M cached prefix** (`AGENTS.md` + frozen shared interfaces):

```bash
KIMI_CODE_AGENT_SWARM_MAX_CONCURRENCY=4 kimi
```

```markdown
/swarm Execute the approved design-token migration plan across disjoint slices:
- Shared contract `src/shared/tokens.ts` is frozen (read-only for all coders).
- Slice 1 (`src/features/auth/**`): Replace legacy hex values and add Vitest coverage.
- Slice 2 (`src/features/billing/**`): Migrate to typed SDK client and pass mock integration tests.
- Slice 3 (`src/features/dashboard/**`): Align chart tokens with zero TypeScript errors.
- Halt after 3 consecutive identical test failures and report root cause; never weaken assertions.
```

---

## 3.3 Three-Strike Loop Protection

Enforce three guardrails in `AGENTS.md` and `config.toml`:
1. State root-cause hypothesis before every retry;
2. Hard-stop after `max_retries_per_error = 3` on the same failure;
3. Forbid `@ts-ignore`, `.skip()`, or `|| true` workarounds to fake green CI.

---

## 3-Step Quickstart

1. **Practice the 3-step handoff**: Run `explore → plan → coder` sequentially on one medium PR.
2. **Launch a 2-slice swarm**: Run `KIMI_CODE_AGENT_SWARM_MAX_CONCURRENCY=2 kimi` on two non-overlapping directories and inspect `git diff --stat`.
3. **Run unified verification**: Finish with `npm run typecheck && npm test && npm run build`.

---

## Pitfall Recovery Table

| Failure Mode | Root Cause | Immediate Fix |
| :--- | :--- | :--- |
| Swarm workers flood `429 Too Many Requests` | Uncapped concurrency exceeds account RPM/TPM | Set `KIMI_CODE_AGENT_SWARM_MAX_CONCURRENCY=2` or `3` and batch slices |

## 4.3 Automated Responsive & Accessibility Gate (`scripts/check_ui_a11y.mjs`)

```javascript
import { chromium } from "playwright";

const URL = process.argv[2] || "http://127.0.0.1:4173/";
const VIEWPORTS = [{ name: "mobile", width: 390, height: 844 },
  { name: "tablet", width: 768, height: 1024 },
  { name: "desktop", width: 1440, height: 900 }];

const browser = await chromium.launch();
const page = await browser.newPage();
let failed = false;

for (const vp of VIEWPORTS) {
  await page.setViewportSize({ width: vp.width, height: vp.height });
  await page.goto(URL, { waitUntil: "load" });
  const res = await page.evaluate(() => {
    const overflow = document.documentElement.scrollWidth - document.documentElement.clientWidth;
    const missingAlt = [...document.querySelectorAll("img")]
      .filter((img) => img.offsetParent !== null && !img.getAttribute("alt")).length;
    const unlabeledButtons = [...document.querySelectorAll("button")]
      .filter((b) => b.offsetParent !== null && !b.textContent?.trim() && !b.getAttribute("aria-label")).length;
    return { overflow, missingAlt, unlabeledButtons };
  });
  console.log(vp.name, res);
  if (res.overflow > 0 || res.missingAlt > 0 || res.unlabeledButtons > 0) failed = true;
}

await browser.close();
process.exit(failed ? 1 : 0);
```

## 5.2 Deterministic Financial Tie-Out & Anomaly Scanner (`scripts/financial_audit.py`)

```python
#!/usr/bin/env python3
import json
from dataclasses import dataclass

@dataclass
class PeriodMetrics:
    period: str
    revenue: float
    cogs: float
    operating_cash_flow: float
    capex: float
    total_assets: float
    total_liabilities: float
    total_equity: float
    receivables: float

def analyze_periods(periods: list[PeriodMetrics]) -> dict:
    report, alerts = [], []
    for i, cur in enumerate(periods):
        gross_margin = (cur.revenue - cur.cogs) / cur.revenue if cur.revenue else 0.0
        fcf = cur.operating_cash_flow - cur.capex
        bs_gap = abs(cur.total_assets - (cur.total_liabilities + cur.total_equity))
        dso_ratio = cur.receivables / cur.revenue if cur.revenue else 0.0

        row = {
            "period": cur.period,
            "gross_margin_pct": round(gross_margin * 100, 2),
            "free_cash_flow": round(fcf, 2),
            "balance_sheet_gap": round(bs_gap, 4),
            "receivables_to_revenue_pct": round(dso_ratio * 100, 2),
        }
        if bs_gap > 1.0:
            alerts.append(f"[{cur.period}] Balance sheet does not tie: gap={bs_gap:.2f}")
        if i > 0:
            prev = periods[i - 1]
            rev_g = (cur.revenue - prev.revenue) / prev.revenue if prev.revenue else 0.0
            rec_g = (cur.receivables - prev.receivables) / prev.receivables if prev.receivables else 0.0
            row["revenue_yoy_pct"] = round(rev_g * 100, 2)
            row["receivables_yoy_pct"] = round(rec_g * 100, 2)
            if rec_g - rev_g > 0.15:
                alerts.append(
                    f"[{cur.period}] Receivables growth ({rec_g:.1%}) outpaced revenue growth ({rev_g:.1%}) by >15pp."
                )
        report.append(row)
    return {"metrics": report, "alerts": alerts}

if __name__ == "__main__":
    sample = [PeriodMetrics("FY2024", 1200.0, 540.0, 260.0, 75.0, 2100.0, 950.0, 1150.0, 180.0),
        PeriodMetrics("FY2025", 1380.0, 648.6, 215.0, 90.0, 2420.0, 1140.0, 1280.0, 255.0),]
    print(json.dumps(analyze_periods(sample), indent=2))
```

When Python flags an alert (such as receivables outgrowing revenue by 26.7 percentage points), query the already-cached K3.1 Pro session to pull exact MD&A credit-policy footnotes for pennies.

## 7.2 Automated Deck Brief Compiler (`build_deck_brief.py`)

```python
#!/usr/bin/env python3
import json
from pathlib import Path

def build_deck_brief(metrics: dict, out_md: str) -> None:
    lines = [f"# {metrics['title']}",
        f"- Audience: {metrics['audience']}",
        "- Style: Clean navy executive layout. One data-backed action title and source footnote per slide.",
        "",]
    for idx, slide in enumerate(metrics["slides"], start=1):
        lines.append(f"## Slide {idx}: {slide['action_title']}")
        lines.append(f"- Layout: {slide['layout']}")
        for pt in slide["bullets"]:
            lines.append(f"- Bullet: {pt}")
        if slide.get("table"):
            headers = slide["table"]["headers"]
            lines.append("")
            lines.append("| " + " | ".join(headers) + " |")
            lines.append("| " + " | ".join(["---"] * len(headers)) + " |")
            for row in slide["table"]["rows"]:
                lines.append("| " + " | ".join(map(str, row)) + " |")
        lines.append(f"- Source: {slide['source']}")
        lines.append("")
    Path(out_md).write_text("\n".join(lines), encoding="utf-8")

if __name__ == "__main__":
    sample = {
        "title": "Q4 Engineering Velocity & Multimodal Cost Review",
        "audience": "Executive & Architecture Committee",
        "slides": [{
                "action_title": "K3.1 Pro prefix caching cut long-document audit cost by 78%",
                "layout": "Left summary card + right comparison bar chart",
                "bullets": ["86% steady-state prefix cache hit rate", "P95 review time reduced from 42m to 6m"],
                "table": {
                    "headers": ["Approach", "Cost / Audit (USD)", "Human Review"],
                    "rows": [["Legacy RAG", "1.45", "42 min"], ["K3.1 Pro + Cache", "0.32", "6 min"]],
                },
                "source": "Internal Billing Telemetry (2026-11-26)",
            }],
    }
    build_deck_brief(sample, "deck_brief.md")
    print("Generated deck_brief.md")
```

# Run: blender --background --python blender_scene_check.py
import bpy
import math

bpy.ops.wm.read_factory_settings(use_empty=True)

bpy.ops.mesh.primitive_grid_add(x_subdivisions=48, y_subdivisions=48, size=12.0, location=(0, 0, 0))
terrain = bpy.context.active_object
terrain.name = "CanyonTerrain"
for v in terrain.data.vertices:
    x, y = v.co.x, v.co.y
    v.co.z = max(-0.4, abs(x) * 0.45 + 0.25 * math.sin(x * 1.1) * math.cos(y * 0.9) - 1.2)

bpy.ops.mesh.primitive_plane_add(size=12.0, location=(0, 0, -0.25))
bpy.context.active_object.name = "StreamSurface"

bpy.ops.object.light_add(type="SUN", location=(6, -6, 10))
sun = bpy.context.active_object
sun.data.energy = 3.5
sun.rotation_euler = (math.radians(48), math.radians(15), math.radians(32))

bpy.ops.object.camera_add(location=(0, -9.5, 4.2), rotation=(math.radians(68), 0, 0))
bpy.context.scene.camera = bpy.context.active_object

scene = bpy.context.scene
scene.render.engine = "CYCLES"
scene.cycles.samples = 24
scene.render.resolution_x = 960
scene.render.resolution_y = 540
scene.render.filepath = "//preview_render.png"
bpy.ops.render.render(write_still=True)
```

## 1.3 一键部署 Kimi Code CLI：`kimi` 终端与 `kimi web` 双形态

2026 年的 **Kimi Code CLI** 已完成从早期 Python 版本到 **TypeScript 原生重构**，冷启动速度、流式渲染与子代理隔离能力全面升级，支持三种工作形态：
- **`kimi`**：目录级终端交互 TUI，直接读写代码、执行 Shell、挂载 MCP 并调用内置子代理；
- **`kimi web`**：在本地起一个轻量 Web 会话工作台，方便带代码高亮、Diff 审阅和历史会话筛选的可视化操作；

```bash
# 1. 全局安装最新 TypeScript 版 Kimi Code CLI（Node.js >= 20）
npm install -g @moonshot-ai/kimi-code

# 2. 配置 API Key（写入本机受控环境，切勿提交到仓库）
export MOONSHOT_API_KEY="sk-your-moonshot-key"

# 3. 核验版本并进入当前项目根目录启动交互式指挥舱
kimi --version
cd /path/to/your-repo
kimi

# 4. 或者启动本地浏览器可视化工作台（自动绑定本机回环地址）
kimi web --port 4310
```

## 2.1 零摩擦配置：`~/.kimi-code/config.toml` 与 `AGENTS.md` 继承

Kimi Code 将运行时配置拆分为两个清爽文件：
- `~/.kimi-code/config.toml`：模型、供应商端点、权限审批档位、多智能体并行上限与 MCP 配置；
- `~/.kimi-code/tui.toml`：终端主题、快捷键与界面排版偏好。

以下是配套套件 [examples/kimi-k3-kit/config.toml](https://github.com/aipmer/codex-blue-book/blob/main/examples/kimi-k3-kit/config.toml) 的生产基线：

```toml
default_model = "kimi-k3.1-pro"
approval_mode = "always_ask"

[providers.moonshot]
base_url = "https://api.moonshot.ai/v1"
api_key_env = "MOONSHOT_API_KEY"
prompt_caching = true

[swarm]
max_concurrency = 4
worktree_isolation = true

[subagents.explore]
model = "kimi-k3.1-pro"
read_only = true

[subagents.plan]
model = "kimi-k3.1-pro"
read_only = true

[subagents.coder]
model = "kimi-k3.1-pro"

[mcp.figma]

args = ["-y", "figma-developer-mcp"]

## 2.2 `kimi acp` 实战：一行接管 Zed 与 JetBrains 编辑器

**ACP（Agent Client Protocol）** 好比智能体世界的 LSP（Language Server Protocol）：编辑器负责展示代码树、Diff 面板、光标选区和内联接受按钮，后端智能体通过标准输入输出（stdio JSON-RPC）接管规划、读文件与跑测试。

```mermaid
flowchart LR
    Zed["Zed Editor"] -->|"stdio JSON-RPC (ACP)"| KACP["kimi acp"]
    JB["JetBrains AI Chat"] -->|"stdio JSON-RPC (ACP)"| KACP
    KACP --> Model["Kimi K3.1 Pro (1M Context)"]
    KACP --> MCP["MCP Servers (Figma / GitHub / DB)"]
```

在 **Zed** 的 `settings.json` 中注册 Kimi Code 只需几行配置：

```json
{
  "agent_servers": {
    "Kimi Code": {
      "command": "kimi",
      "args": ["acp"],
      "env": {
        "KIMI_CODE_AGENT_SWARM_MAX_CONCURRENCY": "4"
      }
    }
  }
}
```

在 **JetBrains（IntelliJ IDEA / PyCharm / WebStorm）** 的 AI Agent 设置中添加 Custom ACP Agent，填入可执行命令 `kimi` 与参数 `acp`。配置完后，无需切出 IDE 就能直接在侧边栏下发任务、逐行审核 Diff 并运行项目单测。

## 3.2 启动 多智能体并行协作与 429 速率平滑控制

在 Kimi Code 中批量重构一个中大型 Web 仓库（例如全站把分散的旧色值与老版请求封装统一迁移到新 Design Tokens 与 Typed SDK）时，最稳的启动姿势是**显式锁死最大并发数**，防止蜂群瞬间把账号 RPM 打爆：

```bash
# 限制最大并发子代理为 4 个，避免触发 429 限流并保持 90% 缓存命中
KIMI_CODE_AGENT_SWARM_MAX_CONCURRENCY=4 kimi
```

进入交互会话后，先跑 `explore` + `plan`，确认切片完全互斥后再下发 `/swarm` 指令：

```markdown
/swarm 按 plan 阶段冻结的清单并行迁移前端模块，严格遵守以下边界：
- 公共类型 `src/shared/tokens.ts` 已冻结，所有 coder 只读不改。
- Slice 1 (`src/features/auth/**`)：替换旧颜色变量并补齐 Vitest 单元测试。
- Slice 2 (`src/features/billing/**`)：替换为新 Typed SDK 并跑通 mock 集成测试。
- Slice 3 (`src/features/dashboard/**`)：迁移图表主题色并验证构建零 TypeScript 报错。
- 任意切片连续 3 次测试失败立即停止并上报根因，禁止盲目改写测试断言绕过报错。
```

### 为什么 \$0.20 缓存读取在蜂群里威力翻倍？
当 4 个并行的 `coder` 共享同一份稳定前缀（`AGENTS.md` + 冻结的 `tokens.ts` + 项目接口定义）时，后续每个并行 Worker 的重复输入都能吃满 **\$0.20/1M（90% 折扣）** 的 Prompt Caching 价格——整轮 40 个文件并行重构下来，总成本往往只相当于一顿工作餐。

## 3.3 终端异常自愈与防死循环硬护栏

并发开发最怕某个 `coder` 碰到棘手报错后陷入“改一行 → 报错 → 改回去 → 又报错”的死循环。在 `AGENTS.md` 与 `config.toml` 中同时立下三条硬规矩：

1. **错误栈三步归因**：连续出错时，必须先输出“报错根因假设 + 本次验证变量”，不得无解释直接重跑同一命令；
2. **三振出局熔断（`max_retries_per_error = 3`）**：同一个编译或单测错误修满 3 轮仍未消失，强制挂起向人工请求决策；

## 4.3 用脚本守住前端视觉与无障碍底线

为了防止后续迭代把刚还原好的页面改回“小字模糊、对比度不足、移动端撑爆”，在仓库 `package.json` 中固化一条轻量 Playwright 验收脚本（`scripts/check_ui_a11y.mjs`）：

```javascript
import { chromium } from "playwright";

const URL = process.argv[2] || "http://127.0.0.1:4173/";
const VIEWPORTS = [{ name: "mobile", width: 390, height: 844 },
  { name: "tablet", width: 768, height: 1024 },
  { name: "desktop", width: 1440, height: 900 }];

const browser = await chromium.launch();
const page = await browser.newPage();
let failed = false;

for (const vp of VIEWPORTS) {
  await page.setViewportSize({ width: vp.width, height: vp.height });
  await page.goto(URL, { waitUntil: "load" });
  const res = await page.evaluate(() => {
    const overflow = document.documentElement.scrollWidth - document.documentElement.clientWidth;
    const missingAlt = [...document.querySelectorAll("img")]
      .filter((img) => img.offsetParent !== null && !img.getAttribute("alt"))
      .length;
    const unlabeledButtons = [...document.querySelectorAll("button")]
      .filter((b) => b.offsetParent !== null && !b.textContent?.trim() && !b.getAttribute("aria-label"))
      .length;
    return { overflow, missingAlt, unlabeledButtons };
  });
  console.log(vp.name, res);
  if (res.overflow > 0 || res.missingAlt > 0 || res.unlabeledButtons > 0) failed = true;
}

await browser.close();
process.exit(failed ? 1 : 0);
```

## 5.2 确定性三表勾稽与异动归因引擎（Python 实战）

拿到 K3.1 Pro 抽取并经过原文引用校验的 JSON 后，立刻交给确定性 Python 脚本做勾稽检查（资产 = 负债 + 所有者权益）、毛利率/净利率/自由现金流计算以及同比异动报警。

下面是一段零外部复杂依赖、可直接运行的财务勾稽与异动扫描脚本（`scripts/financial_audit.py`）：

```python
#!/usr/bin/env python3
import json
import sys
from dataclasses import dataclass

@dataclass
class PeriodMetrics:
    period: str
    revenue: float
    cogs: float
    operating_cash_flow: float
    capex: float
    total_assets: float
    total_liabilities: float
    total_equity: float
    receivables: float

def analyze_periods(periods: list[PeriodMetrics]) -> dict:
    report = []
    alerts = []

    for i, cur in enumerate(periods):
        gross_margin = (cur.revenue - cur.cogs) / cur.revenue if cur.revenue else 0.0
        fcf = cur.operating_cash_flow - cur.capex
        bs_gap = abs(cur.total_assets - (cur.total_liabilities + cur.total_equity))
        dso_ratio = cur.receivables / cur.revenue if cur.revenue else 0.0

        row = {
            "period": cur.period,
            "gross_margin_pct": round(gross_margin * 100, 2),
            "free_cash_flow": round(fcf, 2),
            "balance_sheet_gap": round(bs_gap, 4),
            "receivables_to_revenue_pct": round(dso_ratio * 100, 2),
        }

        if bs_gap > 1.0:
            alerts.append(f"[{cur.period}] Balance sheet does not tie: gap={bs_gap:.2f}")

        if i > 0:
            prev = periods[i - 1]
            rev_growth = (cur.revenue - prev.revenue) / prev.revenue if prev.revenue else 0.0
            rec_growth = (cur.receivables - prev.receivables) / prev.receivables if prev.receivables else 0.0
            row["revenue_yoy_pct"] = round(rev_growth * 100, 2)
            row["receivables_yoy_pct"] = round(rec_growth * 100, 2)
            if rec_growth - rev_growth > 0.15:
                alerts.append(
                    f"[{cur.period}] Receivables growth ({rec_growth:.1%}) outpaced revenue growth ({rev_growth:.1%}) by >15pp — inspect credit policy / channel stuffing."
                )
        report.append(row)

    return {"metrics": report, "alerts": alerts}

if __name__ == "__main__":
    sample = [PeriodMetrics("FY2024", 1200.0, 540.0, 260.0, 75.0, 2100.0, 950.0, 1150.0, 180.0),
        PeriodMetrics("FY2025", 1380.0, 648.6, 215.0, 90.0, 2420.0, 1140.0, 1280.0, 255.0),]
    print(json.dumps(analyze_periods(sample), indent=2, ensure_ascii=False))
```

当脚本抓出 `Receivables growth (+41.7%) outpaced revenue growth (+15.0%)` 这类硬警报后，再带着这个精确问题回到已经缓存好全文的 K3.1 Pro 会话里追问管理层讨论与分析（MD&A）和应收账款账龄附注——**只花几分钱缓存费，就能拿到分析师级别的深度归因。**

- **精确法条 / 定义词全量召回**：对强依赖逐字条文比对的既有合规模板，可先用精确正则/索引加 `kimi-k3` 扫描全部定义项；

## 7.1 三步工程化出稿法：拒绝“一句话抽盲盒”

直接丢一句“帮我做个 AI 行业报告 PPT”给任何工具，结果都是空洞废话。高质量交付必须把 Kimi Slides 当成**编译器的后端渲染器**，先喂干净的结构化前端输入：

```mermaid
flowchart LR
    Raw["原始财报 / 论文 / 遥测 CSV"] --> Distill["步骤 1: K3.1 Pro 蒸馏为分镜大纲 JSON (含每页核心论点 + 数据数组)"]
    Distill --> Slides["步骤 2: Kimi Slides 生成母版版式与原生图表"]
    Slides --> Refine["步骤 3: 局部对话精修 (Talk to the Deck) + 导出可编辑 .pptx"]
```

1. **先冻结分镜大纲（Storyline First）**：规定总页数（如 10 页）、每页只承载 1 个核心结论（Action Title，不是“财务情况”，而是“FY25 毛利率承压 2.1pp，主因海外物流费率上行”），以及每页配什么图表类型（柱状、折线、对比表或架构流程）。
2. **原图架构重建与原生图表**：遇到旧 PDF 里的模糊流程图或扫描数据表，让 Kimi 提取节点与数值后重建为清晰矢量元素与原生 PowerPoint 图表，彻底告别糊成马赛克的截图粘贴。
3. **局部对话式精修**：只针对不满意的第 4 页、第 7 页下达精确修改指令（如“把右侧三列卡片收紧为 2×2 对比矩阵，底部补一行口径说明”），避免整套推翻重来。

## 7.2 自动化周报 / 投委会材料的前置组装脚本

如果你的团队每周都要从数据库、CI 报告或第 5 章的财务勾稽脚本出固定格式汇报，可以写一个轻量组装脚本，把实时指标编译成标准 **Slide Deck Brief Markdown**，一键投喂 Kimi Slides 或通过 `python-pptx` 在 CI 中实现完全离线批量出稿：

```python
#!/usr/bin/env python3
"""
将结构化业务指标编译为 Kimi Slides 高质量分镜输入稿（零外部依赖）。
"""
import json
from pathlib import Path

def build_deck_brief(metrics: dict, out_md: str) -> None:
    lines = [f"# {metrics['title']}",
        f"- 受众：{metrics['audience']}",
        f"- 风格：深蓝商务极简，禁止空泛口号，每页保留 1 条带数据动作标题与数据来源脚注。",
        "",]
    for idx, slide in enumerate(metrics["slides"], start=1):
        lines.append(f"## Slide {idx}: {slide['action_title']}")
        lines.append(f"- 版式建议：{slide['layout']}")
        for pt in slide["bullets"]:
            lines.append(f"- 要点：{pt}")
        if slide.get("table"):
            headers = slide["table"]["headers"]
            lines.append("")
            lines.append("| " + " | ".join(headers) + " |")
            lines.append("| " + " | ".join(["---"] * len(headers)) + " |")
            for row in slide["table"]["rows"]:
                lines.append("| " + " | ".join(map(str, row)) + " |")
        lines.append(f"- 数据出处：{slide['source']}")
        lines.append("")

    Path(out_md).write_text("\n".join(lines), encoding="utf-8")

if __name__ == "__main__":
    sample = {
        "title": "Q4 研发效能与多模态成本复盘",
        "audience": "管理层与技术委员会",
        "slides": [{
                "action_title": "接入 K3.1 Pro 缓存后，长文档审计单次成本下降 78%",
                "layout": "左结论卡片 + 右对比柱状图",
                "bullets": ["前缀缓存命中率稳定在 86%", "P95 审阅耗时从 42 分钟压降至 6 分钟"],
                "table": {
                    "headers": ["方案", "单次成本 (USD)", "人工复核耗时"],
                    "rows": [["旧版 RAG", "1.45", "42 min"], ["K3.1 Pro + 缓存", "0.32", "6 min"]],
                },
                "source": "内部 Billing Telemetry (2026-11-26)",
            }],
    }
    build_deck_brief(sample, "deck_brief.md")
    print("Generated deck_brief.md")
```

# Ch.08 空间智能与 3D Make 实战：从 Web 3D 交互、Blender 到 FreeCAD 机械装配

> **本章解决的工程麻烦**：传统文生 3D 模型生成的是“表面一团烂网格、尺寸全靠猜、完全没法改参数”的不可编辑文件——既没法放进机械 CAD 做精确装配，也没法控制 Web 3D 场景的面数和材质逻辑；而纯手工写 Three.js、Blender `bpy` 或 FreeCAD Python 脚本门槛又太高。
>
> **实战落地收益**：吃透 **Kimi K3.1 Pro 空间编码（Spatial Coding）+ 3D Make** 工作流，落地三条可参数化复现的 3D 工程管线：**Web 3D（Three.js）**、**无头 Blender 场景脚本（`bpy`）** 与 **FreeCAD 参数化机械装配体（`.step` / `.stl`）**。
>
> **一句话结论**：程序化代码生成的 3D 资产天然带精确毫米尺寸、版本控制与一键改参能力——这是 K3.1 Pro 区别于普通图片/网格生成器的真正硬实力。

2026 年底 `@Kimi_Moonshot` 社区里传阅度最高的一组实战演示，既不是写贪吃蛇，也不是画海报，而是两类硬核空间工程作品：一类是 **Blender 程序化室内热带雨林峡谷**（精准控制地形、植被分布、体积光与水体反射），另一类是 **Python + FreeCAD 精密涡扇发动机参数化建模与爆炸视图**。

它们背后的共同密码叫 **Spatial Coding（空间编码）**——不是直接“画”出一坨像素或三角面，而是让具备强几何推理能力的 K3.1 Pro 直接输出可执行的三维建模代码。

## 8.2 管线一：无头 Blender（`bpy`）程序化环境构建与自动审图

受官方“室内热带雨林峡谷”程序化建模启发，最稳的 Blender AI 工作流不是盲目生成上千行脚本一次跑完，而是采用 **“代码生成场景 → 无头渲染三视角预览图 → 喂回 MoonViT-V2 检查穿模与光影 → 自动迭代修复”** 的视觉闭环：

```python
# blender_scene_check.py — 无头构建基础地形+水体+太阳光并输出渲染预览
# 运行命令: blender --background --python blender_scene_check.py
import bpy
import math

bpy.ops.wm.read_factory_settings(use_empty=True)

# 1. 创建程序化微地形平面
bpy.ops.mesh.primitive_grid_add(x_subdivisions=48, y_subdivisions=48, size=12.0, location=(0, 0, 0))
terrain = bpy.context.active_object
terrain.name = "CanyonTerrain"
for v in terrain.data.vertices:
    x, y = v.co.x, v.co.y
    canyon = abs(x) * 0.45
    ripple = 0.25 * math.sin(x * 1.1) * math.cos(y * 0.9)
    v.co.z = max(-0.4, canyon + ripple - 1.2)

# 2. 创建水面平面
bpy.ops.mesh.primitive_plane_add(size=12.0, location=(0, 0, -0.25))
water = bpy.context.active_object
water.name = "StreamSurface"

# 3. 布置主光与相机
bpy.ops.object.light_add(type="SUN", location=(6, -6, 10))
sun = bpy.context.active_object
sun.data.energy = 3.5
sun.rotation_euler = (math.radians(48), math.radians(15), math.radians(32))

bpy.ops.object.camera_add(location=(0, -9.5, 4.2), rotation=(math.radians(68), 0, 0))
bpy.context.scene.camera = bpy.context.active_object

# 4. 渲染低采样快速审图 PNG 供 MoonViT-V2 视觉核验
scene = bpy.context.scene
scene.render.engine = "CYCLES"
scene.cycles.samples = 24
scene.render.resolution_x = 960
scene.render.resolution_y = 540
scene.render.filepath = "//preview_render.png"
bpy.ops.render.render(write_still=True)
```

每跑完一轮 `blender --background --python ...`，直接把生成的 `preview_render.png` 丢回 Kimi Code，让 MoonViT-V2 核对物体是否悬空、穿模、曝光过曝，两三轮即可收敛到稳定成片。

## 8.3 管线二：Python + FreeCAD 参数化涡扇叶轮生成与可打印导出

做工业零件或 3D 打印模型，最致命的错误是网格非流形（Non-Manifold）或壁厚太薄打印就裂。用 **FreeCAD B-Rep 实体建模** 从源头消灭破面问题。

配套套件 [examples/kimi-k3-kit/scripts/freecad_turbine_blade.py](https://github.com/aipmer/codex-blue-book/blob/main/examples/kimi-k3-kit/scripts/freecad_turbine_blade.py) 演示了一个完整可运行的参数化叶轮转子生成器——支持在没有装 FreeCAD 的普通 Python 环境下先用 `--dry-run` 校验叶片弦长、最小壁厚（`>= 1.6mm`）和角度均分，再用 `freecadcmd` 直接导出精密 `.step`（供 SolidWorks / Fusion 360 二次加工）或 `.stl`（直接进切片软件 3D 打印）：

```bash
# 1. 纯 Python 预检几何约束（确保壁厚 >= 1.6mm 且叶片分布无干涉）
python3 examples/kimi-k3-kit/scripts/freecad_turbine_blade.py \

## 9.1 开源权重私有化选型：vLLM / SGLang 部署架构

在规划内网 GPU 集群前，先按客户预算与实际模型体量实事求是地分级（切勿拿消费级单卡硬扛 2.8T MoE）：

| 客户规模与算力预算 | 推荐开源基座 | 典型部署形态 | 适用业务场景 |
| :--- | :--- | :--- | :--- |
| **大型金融机构 / 央国企 / 云厂商专有区** | **Kimi K3.1 Pro**（~2.8T MoE / FP8 量化权重） | 多节点 H200 / B200 集群 + **vLLM / SGLang**（TP + EP 专家并行 + Prefix Caching） | 全行级投研审计、百万字合规与跨仓库内部编程中台 |
| **中型律所 / 研发中心 / 区域医院** | **Kimi K2.5** 或领域微调版 | 单机 8×H100 / H20 + **SGLang / vLLM** | 部门级合同审查、病历结构化与内部知识库问答 |
| **无自建 GPU 但要求数据不入公网** | 专属 VPC 托管端点（云上隔离实例） | 客户云账号内按小时拉起专用推理实例 | 阶段性并购尽调项目、年度审计高峰期弹性扩容 | > **授权合规提醒**：上线商业产品前，务必核对 Hugging Face 上 `moonshotai/` 对应仓库当日的 **Open-Weights License 条款**（重点核查高营收/大月活场景的署名与商用边界），保留完整合规备案记录。

以下是使用 **vLLM** 启动兼容 OpenAI `/v1/chat/completions` 接口、并开启前缀缓存与工具调用解析的标准内网启动模板（以实际拉取的本地权重路径与集群并行度为准）：

```bash
# 私有化内网推理网关启动示例（按集群实际 GPU 数量调整 --tensor-parallel-size / --data-parallel-size）
vllm serve /models/moonshotai/Kimi-K3.1-Pro \
  --served-model-name kimi-k3.1-pro \
  --host 127.0.0.1 \
  --port 8000 \
  --tensor-parallel-size 8 \
  --enable-expert-parallel \
  --enable-prefix-caching \
  --enable-auto-tool-choice \
  --tool-call-parser kimi_k2 \
  --max-model-len 262144 \
  --api-key "${INTERNAL_VLLM_KEY}"
```

一旦内网网关跑起来，你的业务代码和员工电脑上的 **Kimi Code CLI** 完全无需重写，只需把 `~/.kimi-code/config.toml` 的 `base_url` 指向内网网关地址：

```toml
default_model = "kimi-k3.1-pro"

[providers.moonshot]
base_url = "https://llm-gateway.corp.internal/v1"
api_key_env = "INTERNAL_VLLM_KEY"
prompt_caching = true
```
