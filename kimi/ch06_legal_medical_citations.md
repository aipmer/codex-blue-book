# Ch.06 法律合规与生物医药实战：超长文献交叉推理与零幻觉引用校验

> **本章解决的工程麻烦**：法务审查一份 120 页并购主协议加 6 份附件时，第 3 条赔偿上限和附件四的例外条款互相打架，人工翻漏一条就是百万级敞口；临床科研交叉比对几十篇试验方案和不良反应报告时，大模型偶尔编造一段“听起来很像真的”参考文献，直接毁掉整份综述。
>
> **实战落地收益**：建立 **法律合规（条款冲突扫描）+ 生物医药（跨文献证据链）** 的长上下文工程架构，掌握 K3 与 K3.1 Pro 混合路由技巧，并落盘配套零依赖脚本 `verify_citations.py` 对每一条模型结论做**原文逐字引用核验**。
>
> **一句话结论**：在法律与医药领域，没有原文逐字锚点支撑的 AI 结论等于零；把大模型当“高通量线索发现引擎”，把确定性字符串/索引脚本做成发版前的零幻觉拦截闸。

法律与生物医药有两个共同工程特征：**文档极长、跨文件隐蔽矛盾极多、对编造事实的容忍度绝对为零。**

靠“请在提示词里写上‘不要编造’”解决不了合规风险。真正能交付给律所合伙人或药企临床团队的系统，必须在程序层把每一条发现锁死到原文字符。

## 6.1 法律与税务尽调：跨合同冲突扫描与混合路由

企业并购或跨境合规审查时，风险很少孤立藏在某一句话里，而是藏在“主合同第 8.2 条定义了广义关联方，但补充协议附件 B 悄悄把某境外子公司排除在外”这种跨页联动里。

Kimi K3.1 Pro 1M 窗口允许一次性装载全套交易文件（MSA + DPA + 补充协议 + 历史往来函），配合 **K3 与 K3.1 Pro 混合路由** 效果更稳：
- **精确法条 / 定义词全量召回**：对强依赖逐字条文比对的既有合规模板，可先用精确正则/索引加 `kimi-k3` 扫描全部定义项；
- **复杂跨条款逻辑推演与风险评级**：交给 `kimi-k3.1-pro`（\$2/\$10，缓存读 \$0.20）分析条款互相覆盖关系，并强制输出结构化 JSON（每条结论必须附带至少 12 个字符的 `quote` 原文逐字摘录）。

## 6.2 生物医药与临床文献交叉证据链

医药研发团队在立项调研、药物警戒（Pharmacovigilance）和临床方案设计阶段，往往要同时交叉比对数十篇 PDF 论文、FDA 审评报告与试验入排标准。

借助 K3.1 Pro 在长上下文科研交叉推理（如 *BioMysteryBench* 基准）上的高召回表现，可以搭建三步证据链管线：
1. **结构化文献入库**：统一抽取每篇文献的样本量（`n`）、给药剂量、终点指标（Primary Endpoint）、不良事件（AE）及对应页码/段落原文；
2. **跨文献矛盾扫描**：在 1M 窗口中横向比对不同试验的入排标准差异与相互矛盾的次要终点结果；
3. **人工专家仲裁队列**：系统绝不直接下临床结论，只输出带原文高亮锚点的“证据矩阵 + 冲突清单”，供医学事务专家快速复核签字。

## 6.3 零幻觉硬门禁：`verify_citations.py` 原文逐字拦截

只要你的工作流涉及金融、法律或医药，务必在模型输出和最终报告渲染之间插一道**确定性原文核验脚本**。

配套套件中的 [examples/kimi-k3-kit/scripts/verify_citations.py](https://github.com/aipmer/codex-blue-book/blob/main/examples/kimi-k3-kit/scripts/verify_citations.py) 不依赖任何第三方库，自动对 JSON 报告里每一条 `{claim, quote}` 做空白归一化逐字匹配——只要出现哪怕一条编造或改写过字眼的引用，脚本立刻输出失败清单并以退出码 `2` 阻断下游导出：

```bash
# 1. 运行内置正反例自测（验证真引用放行、编造引用拦截）
python3 examples/kimi-k3-kit/scripts/verify_citations.py --self-test

# 2. 在真实尽调/文献流水线中作为发版前门禁运行
python3 examples/kimi-k3-kit/scripts/verify_citations.py \
  --source filings/acquisition_msa.txt \
  --report outputs/kimi_risk_findings.json
```

如果脚本返回退出码 `2`，程序自动把失败条目列表退回给已经缓存了全文的 K3.1 Pro 会话要求“重新定位原文逐字片段，若原文确无此表述则删除该条结论”，最多重试 2 轮后仍不通过则标记为 `UNVERIFIED_NEEDS_HUMAN` 交由人工仲裁。

## 新手极速上手 3 步走

1. **跑通零幻觉核验自测**：执行 `python3 examples/kimi-k3-kit/scripts/verify_citations.py --self-test`，确认输出中 `pass_case.status === "PASS"` 且 `fail_case.status === "BLOCKED_UNVERIFIED_CITATIONS"`。
2. **用一份脱敏合同实战**：把一份公开 SaaS 服务条款（ToS）喂给 `kimi-k3.1-pro`，要求仅按 `[{"claim": "...", "quote": "..."}]` 格式提取解约、责任上限与数据归属条款，再跑 `verify_citations.py` 验证 100% 逐字命中。
3. **建立人工复核分级**：把风险分为 `High（强制人工签字）`、`Medium（抽检）` 与 `Unverified（自动隔离）`，永远不让未校验文本直出给终端客户。

## 翻车自救与避坑速查表

| 故障现象 | 致命根因 | 即刻自救方案 |
| :--- | :--- | :--- |
| 模型明明看对了条款，却被 `verify_citations.py` 判失败 | 模型习惯用省略号 `...` 拼接不连续的两句话，或把英文直引号改成了弯引号 | 在 Prompt 中明确规定 `quote` 必须是原文中连续无删节的子串（禁用 `...`），并在归一化函数里统一标点编码 |
| 扫描 PDF 合同里的数字和条款大面积乱码 | 扫描件未经高质量 OCR，直接抽文本丢失了印章盖住或分栏文字 | 先经高精度表格/文档 OCR 管线转结构化 Markdown，或把关键签署页直接用 MoonViT-V2 视觉核验 |
| 律所或医院法务拒绝把真实合同上传至公有云 API | 客户受数据出境、保密协议或 HIPAA/等保约束 | 直接切至第 9 章的 **K3.1 Pro / K2.5 开源权重内网离线部署方案**，数据全程不出客户机房 | ---
